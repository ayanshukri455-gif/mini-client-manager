# Mini Client Manager

Лек и адаптивен уебсайт за управление на клиенти, изграден с HTML, CSS и чист JavaScript. Проектът не изисква сървър или база данни; клиентите се пазят в `localStorage` на браузъра.

## Функционалности

- Табло със статистика и примерни клиенти.
- Добавяне на клиент чрез форма с име, фирма и имейл.
- Редактиране и изтриване на клиент.
- Търсене по име, фирма или имейл.
- Проверка за дублиран имейл адрес (без значение от главни/малки букви).
- Локално запазване чрез `localStorage`.
- Адаптивен дизайн.

## Стартиране на сайта

1. Клонирай repository-то и отвори папката във Visual Studio Code.
2. Отвори `index.html` в браузър или използвай Live Server.

## Автоматизирани тестове

### Защо Playwright?

Използваме **Playwright** с Chromium за end-to-end (E2E) тестове. Той управлява истински браузър и проверява целия потребителски процес — от попълването на формата до показването и запазването на данните. Това е подходящо за проект, чиято основна функционалност е взаимодействието с HTML интерфейса. Не е необходимо приложението да има сървър или база данни.

### Инсталиране

Необходими са Node.js 22 и npm. В основната папка на проекта изпълни:

```bash
npm install
npx playwright install chromium
```

### Стартиране

```bash
npm test
```

Playwright автоматично стартира локалния сайт чрез Vite и изпълнява тестовете в Chromium.

Полезни команди:

```bash
npm run test:headed   # Показва браузъра по време на тестовете
npm run test:report   # Отваря HTML отчета от последното изпълнение
```

### Какво се тества

| № | Проверка | Очакван резултат |
|---|---|---|
| 1 | Добавяне на клиент | Новият клиент се появява в таблицата и броячът се увеличава |
| 2 | Редактиране на клиент | Името, фирмата и имейлът се актуализират |
| 3 | Изтриване на клиент | След потвърждение клиентът се премахва |
| 4 | Запазване след презареждане | Добавеният клиент остава видим след reload |
| 5 | Дублиран имейл | Формата показва грешка и клиентът не се добавя |

Всеки тест започва с чисто локално хранилище, така че резултатите да не зависят един от друг.

### Резултати от тестовете

GitHub Actions изпълнява същите тестове автоматично при push към този feature branch и при Pull Request към `main`. След изпълнение резултатът (успешни/неуспешни тестове) се вижда в раздела **Actions** на GitHub, а HTML отчетът се качва като artifact с име `playwright-report`.

**Важно:** Не отбелязваме тестовете като преминали предварително. Реалният резултат се попълва от Playwright/GitHub Actions след изпълнението им.
